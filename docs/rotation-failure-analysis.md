# BTC/ETH Rotation Failure Analysis

## Вывод

Результат Iteration 2 остаётся **`NO CANDIDATE`**. Технических ошибок,
объясняющих убыточность Validation, не обнаружено. Убыток воспроизводится из
фактических fills и FIFO accounting: четыре из шести завершённых Validation
эпизодов были убыточными, а оставшаяся открытая ETH-позиция имела отрицательный
unrealized PnL.

Анализ не изменяет торговые правила, параметры, BacktestEngine или SQLite.
Он использует те же `RelativeMomentumRotationPlanner`, `StrategyRunner`,
`BacktestEngine.run_portfolio()` и `PortfolioAccounting`, что и Iteration 2.

## Артефакты и методика

- `reports/rotation-episodes.csv` — 64 строки: 31 закрытый эпизод непрерывного
  full-range прогона, а также отдельные Development, Validation и Studied Test
  прогоны с собственным начальным капиталом. Открытые позиции Development и
  Validation записаны отдельными строками со статусом `open`.
- `reports/rotation-validation-decisions.csv` — все 31 еженедельное решение
  изолированного Validation-прогона.
- `scripts/analyze_rotation_failure.py` — воспроизводит оба CSV, проверяет
  accounting и печатает основные диагностические показатели.

`run_scope` не позволяет случайно суммировать непрерывный full-range прогон и
его изолированные подпериоды. В full-range два эпизода пересекают границы:
эпизод 22 идёт из Development в Validation, эпизод 28 — из Validation в
Studied Test. Поэтому full-range PnL нельзя получить сложением результатов
трёх независимо капитализированных периодов.

Для закрытого эпизода:

- `gross_pnl = SELL quote_notional - BUY quote_notional`;
- `net_pnl = gross_pnl - entry_fee - exit_fee`;
- slippage уже включён в execution prices и, следовательно, в gross/net PnL;
- `modeled_slippage` — отдельная fill-level диагностическая оценка, которую
  нельзя ещё раз вычитать из net PnL;
- MAE/MFE рассчитываются по low/high свечей от execution open входа до свечи
  перед execution open выхода, относительно фактической цены входа;
- открытая позиция оценивается по последнему close без гипотетического SELL.

Для каждого scope выполнено точное равенство:

```text
gross trading PnL - fees = total PnL
total PnL = realized PnL + unrealized PnL
total PnL = final equity - 1,000 USDT
```

В Validation исполненный gross PnL равен -313.30 USDT. Комиссии 11.12 USDT
увеличили итоговый убыток до -324.42 USDT. Комиссии составили 3.55% абсолютной
величины gross PnL. Fill-level slippage равен 5.56 USDT, или 1.77% абсолютного
gross PnL, но он уже отражён в ценах исполнения. Точный контрфактический эффект
нулевого slippage потребовал бы повторного моделирования с другими quantities
и compounding; простое прибавление 5.56 USDT некорректно.

С учётом открытой позиции BTC дал 41.29% Validation-убытка (-133.96 USDT), ETH
— 58.71% (-190.46 USDT). В ETH-часть включены -24.11 USDT unrealized PnL.

## Проверки корректности

Все проверки прошли для full range и трёх изолированных периодов:

- каждый momentum повторно совпал с `close[t] / close[t-720] - 1`;
- решение использует только close текущей и прошлых свечей;
- `signal_available_time` равен следующему hourly open;
- каждый fill исполнен строго на этом следующем open;
- при ETH→BTC порядок fills — SELL, затем BUY;
- сумма fill fees совпадает с execution fills, двойного списания нет;
- сумма completed-trade PnL совпадает с realized PnL;
- `total PnL = realized + unrealized = final equity - initial cash`;
- quote balance нигде не отрицателен;
- одновременно удерживается не более одного актива;
- intent IDs уникальны.

Признаков технического дефекта, который мог бы исказить Validation-результат,
не обнаружено.

## Подтверждённые выводы и гипотезы

Подтверждено данными:

1. Validation-убыток сформировали четыре закрытых проигрыша и отрицательная
   открытая ETH-позиция; два выигрыша были недостаточны.
2. Наибольшие Validation-потери пришлись на ETH 19–26 сентября, BTC 3–17
   октября, ETH 16–23 января и BTC 23–30 января.
3. BTC отвечает за 41.29%, ETH — за 58.71% итогового Validation-убытка.
4. Validation характеризовался значительно меньшей долей положительного 30d
   momentum, но почти такой же реализованной волатильностью.
5. USDT защитил от двух продолжительных падений, но короткие cash-периоды
   также пропустили положительные движения.

Остаётся гипотезой:

- trailing relative momentum мог входить перед быстрыми разворотами;
- повышенная частота target changes могла усиливать чувствительность к
  whipsaw;
- результаты могли зависеть от конкретной последовательности режимов.

Эти гипотезы не проверялись изменением параметров или альтернативной
стратегией и не являются основанием для оптимизации на уже изученных данных.

## Воспроизведение

```bash
python scripts/analyze_rotation_failure.py \
  --database data/market_data.db \
  --episodes-output reports/rotation-episodes.csv \
  --decisions-output reports/rotation-validation-decisions.csv
```

Скрипт выполняет только чтение SQLite и локальный детерминированный backtest.
Сетевые запросы и реальные ордера отсутствуют.
